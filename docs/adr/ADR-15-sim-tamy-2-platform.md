# ADR-15: SIM-TAMY 2.0 platform shape

Status: Accepted (product owner, 2026-10-28). Implements Blueprint v2.1 within the existing stack.

## Context

Blueprint v2.1 reorganizes the product into four pillars and makes AI-01/02/03 P0. It suggests a
repo skeleton (`services/ai`, `knowledge/`, `/api/...` routes) that does not match this codebase.
The work is split across four parallel streams, which will collide on migrations, shared JSON and
AI schemas unless those are fixed first. The product owner also decided (2026-10-28): content comes
from `docs/knowledge base/` with no separate approval step, mock accounts instead of auth, and no
pilot or buyer research.

## Decision

- **Keep the stack.** FastAPI under `/v1`, `apps/api/app/{domain,engine,ai,services,api}`,
  `content/` YAML, Next.js App Router. Blueprint routes and folders are mapped in
  `docs/v2/contracts.md`.
- **Golden Scenarios are family stories.** GS-A and GS-B extend `FamilyStory` (a `discover` step
  kind, typed input, rubric dimensions) instead of a new engine. The family engine stays the only
  authority for state, votes and scores; typed text is mapped to an allowed intent or choice ID first.
- **Knowledge is content.** `content/knowledge/` holds the source registry and knowledge units
  (`app/domain/knowledge.py`). A release is the content hash of published, usable units; rooms pin
  the release ID at creation and AI-02 cites only from it.
- **Shared contracts land first, in one place.** Migration `0006` holds every 2.0 table/column;
  `app/ai/contracts.py` holds the `ai.intent.v1`, `ai.grounded_reply.v1`, `ai.debrief.v1` schemas;
  i18n is split into one namespace file per stream (`apps/web/lib/i18n/v2/*.json`).
- **Mock identity.** Demo accounts come from `content/demo/institutions.yaml` and travel as an
  `X-Demo-Account` header. No passwords, sessions or tenant hardening (prototype boundary).

## Consequences

- Streams can merge in any order without renumbering migrations; a stream that needs another
  column adds migration `0007+` after rebasing on `main`.
- `docs/openapi.yaml` and `apps/web/lib/api/schema.d.ts` are regenerated by whichever stream
  merges later; they are never hand-merged.
- Existing 1.x flows (solo cases, family stories, replay, instructor) keep working; only the
  navigation changes.
