# Action interpreter dev set (T-071)

`actions_th.jsonl` is a held-out, synthetic set for the `DEV-001` engineering fixture. It is **not** clinical content, not the `PP-001` case, and not evidence of model quality. It must never be presented as a real-demo or clinical validation set. The utterances are original, not copied from `DEV-001/actions.yaml` examples.

Each UTF-8 JSONL row has `case_id`, `variant`, `phase`, `text_th`, `action_ids` (zero or more IDs), and `kind`. Kinds cover direct, colloquial, short, misspelled, ambiguous, irrelevant, and multi-intent messages. Empty labels mean that the Interpreter should not infer an Action from the learner chat. Only `HX` and `COM` Action IDs appear: `DEC` actions belong to the Decision Panel, and `DOC` is not an Interpreter chat action. `C03` and `C04` exercise opposite responses to family pressure; `C04` is an unsafe simulated choice, not an endorsed practice.

This dataset is used by the T-005 Interpreter bench. Its labels are provisional author annotations pending independent Content review. Once Content publishes `PP-001`, create a separately reviewed case-specific set; do not silently relabel these synthetic rows as `PP-001`. Do not tune prompts or lexical examples against these held-out rows and then report performance on the same set.

`make bench` measures the offline mock baseline by default and writes a dated Markdown report to `eval/results/` (ignored by Git). It does **not** choose a production model. To compare real candidates, set `LLM_BASE_URL` and `LLM_API_KEY` in the local environment, then pass candidates and their current, externally verified USD-per-million-token prices, for example `make bench BENCH_ARGS='--candidate mock:mock-model --candidate openai_like:MODEL_ID --price openai_like:MODEL_ID=INPUT_PRICE,OUTPUT_PRICE'`. Never commit credentials or learner utterances to reports. A missing price or unavailable token counts appears as `N/A`, not zero. Reports are measurements for this synthetic fixture only; OD-1 remains open until real models and Generator validation are reviewed.
